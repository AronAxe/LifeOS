# Context Check-In Workflow

## 1. Resolve and inspect sources

Resolve the principal-configured TELOS/context source. Record the exact files available; do not assume a fixed seven-file constitution. If the source is unavailable, report why and stop before asking generic identity questions.

Read the relevant source files and their existing metadata. Use source-control history or file modification time only as fallback freshness evidence.

## 2. Build a read-only review queue

For each substantive section capture:

- file and heading/typed ID;
- concise current statement;
- last trustworthy update/review time, or `unknown`;
- age and threshold if the source defines one;
- completeness concerns such as placeholders, contradictions, or missing evidence;
- why reviewing it now would matter.

Prioritize stale, consequential, contradictory, or explicitly requested items. Do not equate old with wrong.

## 3. Present the opening

Give a concise orientation: sources read, major themes still on file, and the first one to three review candidates. Ask one contextual question at a time, for example:

> G2 still says “…” and was last reviewed about three months ago. Is that still right, completed, or in need of revision?

Do not ask “what is your mission?” when a mission is already present.

## 4. Process the answer

Classify the response as:

- unchanged;
- revise;
- complete/retire;
- add a new item;
- defer;
- stop.

Reflect the proposed interpretation and exact file/section before mutation. If the response is ambiguous, ask the narrow clarification; do not infer a write from “continue.”

## 5. Apply an approved edit

For an approved change:

1. read the latest target again;
2. preserve formatting, stable IDs, and existing metadata conventions;
3. make the narrowest patch;
4. update review metadata only if that convention already exists or was approved;
5. read back the affected section and verify it appears once;
6. retain a durable memory only when the principal accepted a stable fact/decision and the Memory policy calls for it.

Do not regenerate unrelated summaries or reload a local service. No Pulse server is part of this workflow.

## 6. Continue or stop

Proceed to the next highest-value item only while the principal wishes to continue. “Enough,” “later,” and “stop” end the workflow immediately and gracefully. The source itself is the durable state; no hidden interview cursor is required.

## 7. Close

Report reviewed items, verified writes, unchanged decisions, deferred items, and unknown freshness. Distinguish content changes from memory retention or optional follow-up proposals.
