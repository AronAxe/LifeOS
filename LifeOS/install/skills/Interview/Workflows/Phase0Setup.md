# Phase 0 Setup Workflow

Use this workflow only when the principal asks to establish a new TELOS/context source or confirms that an existing configured source should be initialized. It is not an automatic installer phase.

## 1. Discover before asking

Check for an already configured source and inspect any existing material. Search relevant prior sessions and durable memory for established identity, goals, projects, or terminology so the principal is not asked to repeat settled context.

If multiple candidate sources exist, present them and ask which is authoritative. Do not merge them silently.

## 2. Agree on topology

Before creating files, agree on:

- the configured `TELOS_DIR` or equivalent source location;
- which sections/files are desired;
- privacy and backup expectations;
- whether the source is version-controlled;
- whether any derived public profile is wanted;
- whether Hindsight retention is separate, selective, or disabled for this material.

No source path is bundled with HALOS.

## 3. Prepare a dry-run scaffold

Draft the minimal structure in a temporary workspace. Prefer a small, comprehensible corpus over reproducing the historical LifeOS tree. A reasonable starting set is:

- mission or orientation;
- goals;
- current problems/challenges;
- strategies;
- beliefs/models;
- wisdom/lessons;
- active projects.

Use neutral placeholders only where the principal has not supplied content. Do not invent identity claims.

## 4. Review and obtain approval

Show the proposed files, headings, and destination. The principal may approve all, approve selected files, alter the topology, or defer. A generic request to continue does not authorize file creation when an option remains unanswered.

## 5. Write and verify

After approval:

1. create only approved files;
2. preserve any pre-existing content;
3. write the agreed initial statements with source attribution where applicable;
4. read every created/updated file back;
5. report exact paths and unresolved placeholders.

Do not enable plugins, create cron jobs, inject a constitution, generate architecture summaries, call local HTTP reload routes, or retain the entire corpus as memory.

## 6. Transition

Once substantive context exists, continue with `ContextCheckin.md` only if the principal wants to. Otherwise stop with the verified scaffold and a concise list of deferred sections.
