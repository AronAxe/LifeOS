# Harvest Workflow

## 1. Acquire the source

Use the direct source first. Extract a YouTube transcript with the installed transcript capability, fetch articles with web extraction/browser fallback, read local files with the file tool, and preserve raw pasted text. Record title, URL/path, author/publisher when available, and retrieval date.

## 2. Establish comparison context

Inspect the relevant repository/docs and retrieve prior decisions or related memory. Do not label a proposal NEW from recollection alone.

## 3. Mine candidates

For each concrete mechanism or idea, capture source evidence, affected HALOS surface, present state, expected benefit, adaptation effort, failure modes, and confidence. Drop vague observations that cannot name a real target.

## 4. Classify and rank

Use NEW, PARTIAL, DONE, REJECTED, or UNVERIFIED. Rank by evidence-adjusted usefulness and novelty against effort/risk. Separate source claims from your analysis.

## 5. Report proposals

Return a verdict and compact ranked table. Harvest is analytical: do not alter skills, configuration, services, or doctrine in this workflow.

## 6. Retain when authorized

A request to “harvest,” “save,” or “ingest” authorizes source retention within the configured Knowledge/Hindsight contract. Store a concise source record with provenance and key extracted facts, or create the approved knowledge artifact. Verify by reading/recalling the stored item.

If the request asked only “what is useful here,” do not infer persistence. If retention fails, report the exact failure rather than claiming completion.
